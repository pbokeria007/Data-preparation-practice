# ПР6. Подготовка набора данных

Практическая работа №6 по анализу данных на синтетическом журнале обращений в IT-поддержку (service desk).

**Цель работы** — пройти полный цикл подготовки данных к обучению модели, которая заранее замечает нарушение SLA (*Service Level Agreement* — согласованные с клиентом сроки реакции и решения обращений). Сама модель в работе **не строится** — только осмотр, разведка, визуализация и предобработка.

---

## Что внутри

Ноутбук `Бокерия_Полина_ПР6.ipynb` разбит на пять блоков — по одной пройденной практике:

| Блок | Тема | Что сделано |
|------|------|-------------|
| 1 | Основы pandas | осмотр таблицы, выборки через `.loc` / `.iloc`, новый столбец, сохранение фрагмента в CSV |
| 2 | NumPy | массивы, срезы, маски, агрегаты с `nan`-версиями, broadcasting (z-оценка) |
| 3 | Группировка | `groupby`, `pivot_table`, дата из Unix-времени, топ-дни по числу обращений |
| 4 | Визуализация | 4+ графика разных типов: гистограмма, boxplot, тепловая карта корреляций, столбчатая диаграмма |
| 5 | Подготовка данных | дубликаты, пропуски, чистка текста, one-hot, масштабирование, новые признаки |

## Данные

Синтетический датасет генерируется прямо в ноутбуке по персональному **SEED**, поэтому у каждого студента свой вариант.

**Целевая переменная:** `sla_breached` — 1, если срок ответа сорван, 0 если уложились.

**Признаки:**

| Столбец | Смысл |
|---------|-------|
| `ticket_id` | идентификатор обращения |
| `opened_ts` | время открытия в Unix-секундах |
| `department` | отдел: Support, Backend, DevOps, Security, Data |
| `product` | продукт: Cloud, CRM, Billing, Auth, Analytics |
| `priority` | приоритет: Low, Medium, High, Critical |
| `channel` | канал: Email, Slack, Portal, Phone |
| `assignee_level` | уровень исполнителя: Junior, Middle, Senior |
| `client_tier` | тариф клиента: Free, Pro, Enterprise |
| `cpu_pct` | загрузка CPU на затронутом узле, % |
| `memory_mb` | занятая память, МБ |
| `n_reopens` | сколько раз тикет открывали повторно |
| `comments` | число комментариев в тикете |
| `resolve_hours` | часы до закрытия |
| **`sla_breached`** | **цель**: 1 — SLA нарушен, 0 — нет |

## Ключевые результаты разведки

- **Приоритет** — самый сильный фактор: у `Critical` нарушено **77.2 %** тикетов, у `High` — 57.6 %, у `Medium` — 42.5 %, у `Low` — только 33.7 %.
- **Отдел** влияет слабее: хуже всех Security (~51.5 %), лучше всех Data (~43.5 %).
- **Продукт** почти не влияет: разброс 44.5–47.5 %.
- **Корреляции** с `sla_breached`: только `cpu_pct` даёт заметную связь (r ≈ 0.15), у `resolve_hours` — слабая (r ≈ 0.05), у остальных — близко к нулю.

## Новые признаки

| Признак | Формула / смысл | Зачем |
|---------|-----------------|-------|
| `is_critical` | флаг `priority == "Critical"` | самый сильный фактор по EDA |
| `load_score` | `cpu_pct * memory_mb / 1000` | обобщённая нагрузка узла |
| `reopen_rate` | `reopen_count / comments` (с защитой от деления на 0) | частота повторных открытий относительно активности |
| `is_weekend` | тикет открыт в выходной | гипотеза о медленной реакции дежурной смены |

## Примечания

- Датасет полностью синтетический, сгенерирован через `numpy.random.default_rng(SEED)` и не содержит реальных данных.
- Ноутбук намеренно включает «грязные» места (пропуски, дубликаты, разный регистр текста, выбросы) — их обработка и есть суть блока 5.
- Модель машинного обучения в этой работе не строится — только подготовка данных к ней.
